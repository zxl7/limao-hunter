## 一、问题诊断

### 1.1 当前机制现状（实测核查）

| 层 | 机制 | 早盘 9:25-10:00 实际触发 |
|---|---|---|
| **定时快照层** | 盘中快照 ×3（10:00/11:00/14:45）+ 盘中猎手 ×11（09:25~14:30 错峰） | **9 个定时任务**：0925/0927/0930/0935/0940/0945 猎手 + 1000 快照 + 0925 哨兵 + 0927 竞价验证 |
| **守护层** | launchd pulse-fetcher（StartInterval=30s） | 每 30s 刷新 latest.json + 事件检测，**全天约 480 轮** |
| **事件触发层** | live_signal（盘中异动·事件驱动） | 新涨停/冲板预警/涨幅突增/板块异动/快讯点名，动态阈值+当日去重 |

### 1.2 核心问题

1. **定时层过密且重复度高**：9:25-10:00 的 35 分钟内堆了 **9 个定时任务**（5 分钟一个猎手），推送内容高度相似（同一题材反复播报），用户难以提取**爆发性关键数据**——早盘是情绪最激烈、信息价值最高的时段，却被密集同质化推送淹没。
2. **定时快照的固有缺陷**：固定间隔会**错过两轮之间的异动**（如 9:32 冲板、9:37 炸板，9:35 快照正好错过）；且定时推送无「紧急度」区分，普通波动与爆发性异动推送形式相同。
3. **事件层与定时层割裂**：live_signal 已具备完善的动态阈值+去重，但**只在小卡/极短卡触发**，与定时快照的完整卡**互不协同**——事件触发的高价值信号没有反哺定时卡的「本次要点」，定时卡的重复内容也没有被事件层降噪吸收。
4. **无波动自适应**：全部定时任务固定频率，**市场剧烈波动时不加密、平淡时不降频**，与用户「按市场波动动态调整」的诉求不符。

### 1.3 两类机制对比

| 维度 | 定时快照（现用·过密） | 事件触发快照（旧版提示音/live_signal） |
|---|---|---|
| **优点** | ①数据完整（固定节奏不遗漏）②可预测（用户知道何时看）③便于横向对比（同一时刻序列） | ①时效性极高（异动即报）②信息密度高（只报真异动）③降噪（无信号不打扰） |
| **缺点** | ①重复度高（同题材反复推）②错过两轮间异动 ③无紧急度区分 ④频率固定不波动自适应 | ①数据不完整（无信号时段是盲区）②依赖触发条件设计（阈值不当→漏报/误报）③历史可比性弱（触发时点不定） |
| **适用场景** | 盘后复盘、整点全景、横截面对比、趋势序列 | 盘中异动捕捉、冲板预警、炸板/核按钮告警、快讯催化点名 |

## 二、优化方案

### 2.1 9:30-10:00 时段频率设计（核心结论）

**诊断：当前 5 分钟一推过密，应「降频 + 波动自适应」双管齐下。**

| 时段 | 建议频率 | 理由 |
|---|---|---|
| 9:25-9:45（开盘爆发期） | **10 分钟 1 次全景**（9:25/9:35/9:45） | 开盘 30 分钟是情绪定调期，但**事件层已覆盖异动**——全景卡只需 3 次定调，不必每 5 分钟重复 |
| 9:45-10:30（分化期） | **15 分钟 1 次**（10:00/10:15/10:30） | 情绪进入分化，事件层接管异动播报，全景卡降频 |
| 10:30-11:30（午前震荡期） | **30 分钟 1 次**（10:45/11:15） | 稳定期低频，靠事件层抓零星异动 |
| 13:00-14:30（午后回归期） | **30 分钟 1 次**（13:00/13:30/14:00/14:30） | 午后情绪修复/分歧，事件层为主 |
| **波动自适应（全时段）** | 情绪分 **≥7（亢奋）→ 加密 1 档**；**≤2（冰点）→ 降频 1 档** | 亢奋日异动多值得多看，冰点日少打扰 |

> **一句话**：定时全景从「每 5 分钟」降为「开盘 10 分钟/分化 15 分钟/稳定 30 分钟」，腾出的带宽全部交给事件层——**异动由事件层实时报，全景由定时层低频定调**，两类机制职责分离。

### 2.2 触发条件设计（事件层·对齐 live_signal 已验证逻辑）

| 事件 | 触发条件 | 阈值（动态） | 备注 |
|---|---|---|---|
| **冲板预警** | 未封板但接近涨停 | 主板 **7.5%** / 20cm **15%**（情绪分≥3）；保守 8.5%/17%（情绪分<3） | live_signal 已有，保留 |
| **新涨停** | 上轮未涨停→本轮涨停 | 10cm 9.9% / 20cm 19.9% | 当日按 code 仅推 1 次 |
| **强势领涨** | 20cm 未封板涨超 10% | 10% | 提前埋伏窗口 |
| **涨幅突增** | 两轮间涨幅跳升 ≥5% | 5% + 900s 限频 | 捕捉瞬间拉升 |
| **板块级异动** | TOP5 板块涨停 ≥3 | 3 只 + 今日首推 | 去重防刷屏 |
| **炸板/核按钮** | 炸板率>25% / 核按钮≥6 | 见 feedback_matrix | 亏钱效应告警 |
| **快讯催化点名** | 快讯含硬关键词 + 点名个股 | HARD 词表 | 消息→题材→个股映射 |
| **竞价异动**（新增建议） | 9:25 竞价高开 ≥7% 或竞价额超昨日量 10% | 7% / 量比 10% | **补 9:25-9:30 事件盲区** |

### 2.3 消息去重与聚合策略

1. **三重复合去重**（已部分实现，补齐）：
   - **时间窗去重**：同 code 事件 900s 内不重复推（live_signal 已有）
   - **语义去重**：同一题材/同一催化源的信号聚合为一条（标题相似度 >0.7 合并）
   - **当日去重**：同 code 涨停当日仅首推（已有 zt_codes）

2. **信号聚合规则**（新增·核心优化）：
   - **同板块聚合**：同一板块 3 只以上异动 → 聚合为 1 条「板块异动卡」（含龙头+跟随+联动度），不逐只推
   - **同题材聚合**：同一催化源的多个信号（快讯点名+冲板+板块异动）→ 1 条「催化联动卡」
   - **升级聚合**：普通快照期间累计的事件 → 定时卡顶部加「⏱ 距上轮异动」摘要区（事件反哺定时）

3. **分级降噪**（紧急度分层）：
   - **S 级（立即推·提示音）**：新涨停/冲板预警/核按钮≥6/板块涨停≥3——**保留事件式即时告警的时效性**
   - **A 级（实时推·无音）**：涨幅突增/强势领涨/快讯点名
   - **B 级（并入定时卡）**：普通波动/轮动提示——**不单独推，随下一张全景卡带出**

### 2.4 事件 × 定时协同配合（关键设计）

```
【事件层】live_signal（30s 轮询·实时）
  S级事件 → 立即推 + 提示音（时效性保留）
  A级事件 → 实时推（无音）
  B级事件 → 写入 pending_events.json（暂存）
        ↓ 每轮事件带 hhmm 时间戳入队列
【定时层】全景快照（10/15/30min 自适应频率）
  启动时读 pending_events.json →
    ① 未推送事件（S/A 漏推兜底）→ 补推
    ② 聚合为「⏱ 距上轮异动：09:32 共进冲板 7.8% → 09:38 炸板回落」摘要行
    ③ 全量全景卡（涨停/板块/情绪/资金）正常输出
  推送后清空 pending（事件已被全景卡吸收）
```

- **职责分离**：事件层管「现在发生了什么」（实时·精·带音）；定时层管「现在整体什么状态」（全景·全·可比）
- **双向反哺**：事件 → pending → 定时卡摘要（不丢事件）；定时 → 低频释放带宽（不淹没事件）
- **保底兜底**：若事件层故障（守护停摆），定时层仍按节奏出全景，且 pending 中未推事件在下一张定时卡补推——**数据完整性双保险**

### 3.3 告警规则示例（live_signal 扩展）

# 竞价异动（新增·补 9:25-9:30 盲区）
def detect_auction_surge(quote: dict, prev_close: float, prev_amount_yi: float) -> bool:
    """9:25 竞价异动：高开≥7% 或 竞价额≥昨量10% → S级事件"""
    gap = (quote["auction_price"] - prev_close) / prev_close * 100
    amt_ratio = quote["auction_amount_yi"] / max(0.01, prev_amount_yi)
    return gap >= 7.0 or amt_ratio >= 0.10

# 波动自适应频率（快照任务守卫）
def should_snapshot_now(sentiment: float, last_shot_min: int) -> bool:
    """亢奋加密 / 冰点降频"""
    if sentiment >= 7 and last_shot_min >= 15:   return True   # 亢奋：≥15min 就补一档
    if sentiment <= 2 and last_shot_min < 20:    return False  # 冰点：<20min 跳过
    return last_shot_min >= 30                                  # 常规：30min 一档
