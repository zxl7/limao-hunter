## 〇、它是怎么做到「毫秒级扫全 A」的（原理拆解）

**结论：没有算法魔法，是 4 个工程选择叠加的结果。**「毫秒」= 数据早就在本地 + 列结构统一 + 全截面向量化 + 不物化宽表 + 进程内缓存。

| 层 | 做法 | 为什么快 |
|---|---|---|
| ① 存储 | 全 A 日 K 落 **Parquet 分区表**（按日分区）+ **DuckDB** 查询层 | 列存压缩比高、按日分区裁剪 → 只读目标分区那几个文件 |
| ② 计算 | 策略 = 一组 **Polars 表达式**，对「日期 × 标的全截面」**一次求值** | 无 Python 逐股循环；SIMD + 多线程；Rust 内核 |
| ③ 列裁剪/谓词下推 | 只读策略引用的列、只读需要的分区 | IO 量级再降一个数量级 |
| ④ **只存基础列（15 列），68 个指标读取时现算** | 不物化宽表；指标是向量化算出来的 | 磁盘小、读取少；反而比读一张超大宽表更快 |
| ⑤ 进程内快照缓存 | 同一交易日的 enriched 帧常驻内存 | 25 个策略逐个扫 = 只有第 1 次有 IO，后续全走内存 |
| ⑥ 口径单源 | 同一 enriched 帧被 选股/回测/监控/因子检验共用 | 一次算、多方用，且不会口径漂移 |

**量级实证**（其 mining 文档自述）：132 万行 × 243 交易日 × 44 因子做相关矩阵 + 组合搜索 → **峰值内存 1.29 GiB、总耗时 25.1 秒**。可推断单次「全 A × 单日截面扫描」（约 5400 只 × 1 行）在 Polars 里确实是**毫秒级**。

**对我们的启示**：难的从来不是「算得快」，而是**数据得先在自己手里、且列结构统一**。我们现在是「脚本各自抓、JSON 按日落、各脚本自己解析」——算得不慢（因为量小），但**没有一份可复用的全市场截面**，所以每个需求都要重新抓一次。

## 一、A 级：方法论 · 零成本 · 可立刻落地

### A1. 情绪阶段「平滑 + 确认」（**最推荐**）
- **它的做法**：驱动量先 EMA 平滑（α=1/3，约 5 日）→ 再 **2 日确认**（新标签连续 2 日出现才切换）。效果：平均阶段段长 **9.7 天**（其旧版 5 档打分只有 1.1-1.5 天，天天在跳）。
- **我们的现状**：2026-09-10 刚上 `sentiment_ma3` + `turn_signal`（repair/ebb/flat + 背离修正），但**没有平滑、没有确认** → 仍可能出现单日翻转。
- **落地点**：`scripts/gen_sentiment_summary.py` —— 加 `phase_ema`（α=1/3）+ `confirm_2d`（连续 2 日同向才认），输出「待确认」中间态。
- **成本**：小改动（新增两个纯函数 + 卡面一行）。

### A2. 阈值「分位标定 + 全历史回填验收」
- **它的做法**：阈值不拍脑袋 —— 取 2020-08~2026-08 共 **1454 个交易日**的 **p10 / p60 / p90 分位**定线；回填后做**极端期抽查验收**（如 2024-09-24→10-08 应为 启动→主升→高潮；2024-01 微盘崩应为 退潮/冰点；高潮 6 年仅 2 段）。
- **我们的现状**：情绪分档（4.5/7）、核按钮、晋级率 30%、`CLIMAX_PEAK_PCT=0.8`、`CLIMAX_MIN_ZT=10` 等**几乎全是经验值**，无分位依据、无历史验收。
- **落地点**：写一个一次性脚本，用我们已有的 `cache/short_term/daily/emotion_*.json` + `cache/feishu`/`zt_history` 历史序列算分位，输出「阈值建议表 + 历史验收报告」，人工确认后再改常量。
- **成本**：一次性分析脚本（不改生产链路）。

### A3. 弱档否决（跨层优先级铁律）
- **它的做法**：5 档 state ∈ {weak, lean_weak} 时，**正向阶段（主升/高潮/启动）一律降为「修复」**。理由（原话）：连板梯队强但大盘崩的交易日（如 2024-01 微盘流动性危机）会被梯队指标误判为主升。
- **我们的现状**：已有 `break_count≥1 → risk_off`，但**没有显式的「大盘弱势否决梯队强度」**这一条。
- **落地点**：写进宪法【核心判断原则】——「涨停生态与大盘背离时，以大盘弱势为准」，并在 `quant_score`/`decision_outlook` 门控加一条 veto。

### A4. 宽基/风格标签过滤（防垄断）
- **它的做法**：主线排名时，**成员数 > 600 的概念视为宽基/风格标签**（融资融券 ~7700 家、沪深股通 ~3300 家）不参与排名；成员数下限 4；另有名称黑名单。可配置 + 改完秒级重算。
- **我们的现状**：有 `SECTOR_ALIAS`/`flow_noise` 噪声过滤，但**没有成员数阈值**——题材/轮动计数容易被泛标签吃掉。
- **落地点**：`sector_family.py` 加 `SECTOR_MEMBER_CAP`（默认 600）+ 黑名单，复用现有单一源。

### A5. 主线分公式（可直接对照）
- **它的公式**：`主线分 = 0.35×涨停家数 + 0.25×最高板 + 0.25×梯队档位数 + 0.15×二板宽度`（各因子先做当日截面 rank 归一）；**每概念当日涨停 < 3 家不参与排名**；每日持久化 top30。
- **我们的现状**：`board_core.py` 四维（时效/封板硬度/连板领先/带动参与）算的是**个股核心票**，不是**板块排序**；板块排序仍靠 top5 涨停数。
- **落地点**：作为 `board_core` 之外的**板块主线分**，与现有 top5 做交叉验证。

## 二、B 级：工程 / 流程 · 中等成本 · 收益大

### B1. AI 迭代台账协议（**最值钱·强烈推荐**）
> 原文定位：「用 AI 承担生成—诊断—修改的重复劳动，**回测验证与上线决策永远由人完成**」。与我们的 `learning.py` 自学习层是同一件事，但它的纪律远严。

核心机制（可直接照搬到【财神-回测】）：

| 机制 | 具体做法 | 对我们的价值 |
|---|---|---|
| **门槛先于结果写下** | 冷启动时就把判定门槛写进台账（如「夏普≥基线+0.2 且 分年最差>0 且 样本外降幅<10%」） | 防「看完结果找理由」；我们的 learning 目前无此约束 |
| **留出集封存** | 迭代开始即封存最后 20% 区间，任何一轮都不许用；**定型版本只在留出集上跑一次** | 这是对「多轮挑最优」多重检验的最终防线 —— 我们缺 |
| **两阶段节奏** | 粗调期（v1-v4）每轮允许一个「改动主题」；精调期（v5+）**严格单变量一轮一处** | 我们改阈值时常常一次动多个 |
| **分层验证** | 常规轮只跑「扫描初筛 + 核心回测 + 分年」；**终审**（参数敏感性 + 滚动样本外 + 蒙卡）只在判定「拟接受」时触发 | 省算力，重点轮才烧 |
| **负知识** | 台账必记「什么没用、为什么」（原话：**台账里最值钱的部分**） | 我们只记成功，不记失败 |
| **快照链 + 一行回退** | 每次「接受」存 `v{n}.py`；回退 = 复制回当前文件 | 我们的可逆开关是「改常量」，缺版本快照 |
| **停止规则** | 连续 2 轮无改善 / 达成目标 / **满 8 轮强制复盘** | 防无限调参 |
| **证据包固定格式** | 基线 vs 本轮（夏普/回撤/胜率/盈亏比/命中）+ 分年 + 敏感性 + 样本外 + 因子归因 | 我们回测卡已有部分，缺「基线对比 + 分年」 |
| **AI 诊断纪律** | 先逐条复述证据 → 问题按证据强度排序 → **禁引用证据里没有的现象** → 每个问题对应一处最小修改 + 预期指标；**AI 诊断不进判定链** | 我们的 AI 建议目前可直接进链路 |

### B2. 因子归因（胜单 / 败单入场日对比）
- **做法**：对盈利单与亏损单，在**入场信号日**取各因子均值 → 胜单均值 / 败单均值 / 差值 / 样本数，判断某因子是在**筛选**还是在**拖后腿**。
- **成本**：零额外计算（用候选快照）。
- **落地点**：我们的 `candidates-*.json` 已带 `dim_panel`/各因子分 → 可在回测卡加「因子归因」小节。

### B3. 候选「显式发布」+ 晋级门槛硬校验
- **它的门槛**（服务端强制，不满足即拒并返回原因）：非探索档置信度 · **≥2 个有效 outer 折** · **正收益折比例 ≥ 2/3** · **样本外 Sharpe ≥ 0.5** · **最大回撤不劣于 -25%** · **样本外交易数 ≥ 60**。
- **边界**：保存（promote）随时可以，**发布（publish）必须过门槛**；自动任务**永不自动发布**。
- **我们的现状**：`learning.py` 有 `auto_apply`（默认关）+ 幅度钳制 + 回滚快照，但**没有门槛硬校验**这一层。
- **落地点**：给 learning 建议加「样本数 / 命中率 / 回撤」三项门槛，不达标只提示不改值。

### B4. 防未来函数四件套
1. **T-1 环境**：交易日 T 只能用**上一交易日**已得到的环境标签；缺前驱环境 → **fail-closed**（不用当日、不用最近自然日、不用默认值补）。
2. **purge + embargo**：训练与测试之间默认留 **30 个交易日**。
3. **空值不填 0**：缺数据一律 `null` 并从当日截面剔除。
4. **点时口径**：财务因子只在**晚于公告日**的交易日生效（保守取公告次一日起）。

→ 我们 `promo_quant` / `backtest_engine` 可逐条对齐；尤其「fail-closed 不用默认值补」值得进宪法。

### B5. 交易日探针三级降级
- **做法**：日历（确定性，含调休）→ 行情时间戳探针（OR 语义）→ 工作日兜底；节假日自动停掉实时轮询与分钟增量，**零无效请求**。
- **我们的现状**：交易日历靠 akshare `tool_trade_date_hist_sina`（今天刚踩过坑 → 降级手算工作日）。
- **落地点**：加一层「行情时间戳探针」（用 latest.json / 涨停池时间戳反证是否交易日），比纯日历更抗接口故障。

### B6. 单源特征构造器（口径单源）
- **做法**：盘中信号的特征构造器**只有一份**（`intraday_features.py`），监控评估 / 分钟策略 / 分钟回测 / 历史回放**四条路径共用**，保证同一段数据产出完全一致，且只用已收盘 bar（不跨午休/跨日滚动）。
- **对我们的启示**：我们的「涨停判定」目前散在 `zt_genes._is_zt_row` / `feedback_matrix` / `board_core` 等多处 —— 可收敛为单一函数（我们已有先例：`flow_noise.py` 单一源）。

## 三、C 级：架构级 · 大工程 · 暂不建议

| 项 | 说明 | 为什么不建议现在做 |
|---|---|---|
| Parquet 分区表 + DuckDB + Polars 全截面 | 数据仓库化 → 一份可复用全市场截面 | 我们量级小（5400 只 × 日频），现有 JSON 够用；**但若要做全市场分钟级/因子检验，这是必经之路** |
| 能力路由矩阵 + fail-closed | 每个数据集按源声明能力独立路由，未声明即拒 | 我们源少（东财/腾讯/新浪/同花顺），收益有限 |
| spawn 子进程隔离 + SSE 进度 + 持久 run ID | 长任务不丢、可重连 | 我们回测轻量，暂无必要 |

## 四、它值得学的「克制」（文化层）

1. **新旧并存、消费方不动**：新增 6 阶段 phase 时，原来的 5 档 state **原样保留**，明确「不替代任何既有消费方」；且阶段体系**明确不生成任何交易信号，仅供研究分析**。
2. **阈值全部集中在模块顶部常量**，调整只改那里。
3. **诚实标注已知偏差**：如「概念成分是当前快照回看历史 → 越近越准」直接写进文档并随 API 返回；「退潮/冰点天然是短段」「修复是占比最高（~74%）的兜底段」照实说。
4. **明确不做什么**：「不内置 AI 荐股 / 涨停预测」「完全自动赚钱 ❌ 不存在」。

→ 与我们的「可逆开关 + 增量叠加 + 诚实降级 + 宪法单一源」高度同构，可互相印证。
