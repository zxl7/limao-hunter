## 3. 核心指标

### 3.1 第一层：当日双轴（T · 实时）—— 页面主视觉

**关键设计前提（本页的理论根基）**：
「赚钱效应 / 亏钱效应」在 A 股短线语境里 = **昨日出手的人今天赚了还是亏了**。
因此两轴**共用同一个池子**（昨涨停池 `prev_zt_count`），按今日涨跌**分组**，
是天然正交的分解 —— ⛔ 不是硬凑的两套打分。

| 轴 | 指标 | 字段 | 既有档位（照抄 `sentiment_score`） |
|---|---|---|---|
| **赚钱** | 上涨广度 | `up_rate` 昨涨停今上涨占比% | ≥70 / ≥60 / ≥50 / <45 / <35 |
| | 赚钱质量 | `avg_pct` 昨涨停今均涨幅% | >3 / >1 / >−1 / >−3 / else |
| | 强势家数 | `strong_count`（今涨 ≥5%） | 与池子比：`strong/prev_zt_count` |
| | 涨停扩张 | `zt_expand` 今涨停/昨涨停−1 | ≥0.60 / ≥0.30 / ≥0.10 / ≥0 / ≤−0.10 / ≤−0.30 |
| | 接力质量 | `promote_rate` 晋级率% / `lb_promote_rate` 连板晋级% | ≥50 / ≥35 / ≥25 / <15；连板 ≥50 / <30 |
| **亏钱** | 核按钮 | `nuke_count`（昨涨停今跌 <−5%）+ `nuke_list` | ≥5 / ≥3 / ≥1 / 0 |
| | 大面家数 | `big_loss_count`（今跌 ∈[−5%,−3%)） | `(nuke+big_loss)/prev_zt_count` |
| | 真破位 | `break_count`（核按钮中**同时**破 MA5+MA10） | ≥3 / ≥1 |
| | 炸板率 | `broken_rate` | >0.40 / >0.25 / <0.15 |
| | 指数强度 | `idx_avg` 三指数均涨% | ≥2.5 / ≥1.5 / ≤−2.5 / ≤−1.0 |
| | 跌停家数 | `intraday_timeline` 的 `limit_down_new` 累计 | 与涨停家数对比 |

**展示形式**：双轴各一个 5 档定性（强 / 偏强 / 中性 / 偏弱 / 弱）+ 4~6 个原始读数（⛔ 分数是派生的，原始值必须同屏可见）。

⚠️ **两轴可同时高**（结构性行情：龙头赚钱、跟风亏钱）**或同时低**（无量僵局）—— 这正是单轴 `sentiment_score` 覆盖不到的，
也是本页存在的理由。

### 3.2 第二层：历史窗口（T-1 / T-2 / T-3）—— 汇总而非推断

| 指标 | 来源 | 说明 |
|---|---|---|
| 5 日「晋级率 × 溢价」序列 | `feedback_matrix.trend.history[]` = `{date, pr, ap}` | **系统已现成的 5 日双指标序列**（实测 09-15/16/17/18/22） |
| 5 日情绪 / 晋级 / 核按钮序列 | `summary_5d.trajectory.{sentiment_seq, promote_seq, nuke_seq}` | 与 `sentiment_ma3`（3 日均线）同屏 |
| 10 日窗口 | `summary_5d.summary10.days` | 只作**周期定位**，⛔ 不作买卖触发（沿用窗口分层铁律） |
| 逐日晋级事件与**真实溢价** | `promotion/daily`（`promo_<date>.json`，limit 10） | 每票 `prev_boards→boards / stage / ok / prem_open1 / prem_close1 / prem_close2` |
| 阶段归因 | `summary_5d.cycle_why` = `{direction, delta, drivers[], text}` | 例：`情绪 1→8（+7.0）：核按钮 9→1；晋级率 10.1%→25.5%` |

### 3.3 第三层：推演（T+1 / T+2 / T+3 / T+4）

| 视野 | 输出 | 依据 |
|---|---|---|
| **T+1** | **期望晋级家数** + **期望溢价区间** + 期望亏钱侧基线 | 今日池的**板数分布** × `promo_summary` 各阶段历史统计（条件期望） |
| T+2 | 中期溢价经验值 | `promo` 事件的 `prem_close2`（晋级日 T 收盘 → T+2 收盘）分布 |
| T+2 ~ T+4 | **三情景**（延续 / 修复 / 恶化），每情景给触发条件 + 效应档位 | `trajectory.turn_signal`（`dir`/`label`/`ma3_last`/`divergence`）+ `sentiment_ma3` |

⛔ **不做点预测**；⛔ 样本 < 30 只只呈现不裁决（沿用回测纪律 🔁-9）；⛔ 不写「明天涨/跌」这类结论。

**口径冻结（来自 `promo_quant.py` 头部注释）**：
> 次日溢价 = 以**晋级日 T（即 D+1）收盘**为基准 → `prem_open1`(T+1 开盘) / `prem_close1`(T+1 收盘) / `prem_close2`(T+2 收盘)

⇒ 这是**接力打板闭环收益**的测度，正是「赚钱效应」的钱味体现。

## 5. 计算逻辑

### 5.1 历史回顾（T-1 / T-2 / T-3）—— 纯聚合

```
输入：feedback_matrix.trend.history[]（近 5 交易日，系统已算好 {date, pr, ap}）
     + summary_5d.trajectory（sentiment_seq / promote_seq / nuke_seq）
     + promotion/daily（近 10 日的逐票晋级与溢价）

① 序列化：按 date 对齐，输出 4 条微型折线（情绪 / 晋级率 / 核按钮 / 昨涨停今均涨）
② 分阶段真实溢价：对 T-1..T-3 的 promo 事件按 stage 分组求
     成功率 = ok 占比
     成功组溢价均值/中位 = avg/median(prem_open1, prem_close1 | ok)
     失败组开盘均值 = avg(prem_open1 | ¬ok)
③ 拐点：读 summary_5d.trajectory.turn_signal
     dir='repair' → 修复中；'ebb' → 退潮中；'flat' → 震荡
     ⚠️ 必须透传 ebb_warn / repair_warn（「假修复 / 修复前兆」）—— 这是系统的防误判层
④ 缺料规则：任一字段缺失 → 渲染「—」，⛔ 不退化为 0；⛔ 不用别日数据顶替
```

⛔ **本层不做任何推断** —— 所有数字都是已落盘事实的聚合。

### 5.2 未来推演 —— 条件期望 + 三情景

#### (a) T+1 条件期望（可解释、可回测）

```
基线表 B(stage) ← promo_summary.rows（全样本 · 实测 2026-09-23 读取，ts=09-18T17:19）
┌───────┬─────┬────┬────────┬──────────────────┬──────────────────┬───────────────┐
│ stage │  n  │ ok │ succ%  │ 成功组 open 均值/中位│ 成功组 close 均值/中位│ 失败组 open 均值/中位│
├───────┼─────┼────┼────────┼──────────────────┼──────────────────┼───────────────┤
│ 1to2  │ 695 │107 │ 15.4   │ +3.00 / +1.79    │ +2.80 / +3.09    │ −0.71 / −0.44 │
│ 2to3  │  99 │ 34 │ 34.3   │ +4.37 / +5.59    │ +3.70 / +4.53    │ −1.66 / −1.57 │
│ 3to4  │  31 │ 16 │ 51.6   │ +3.65 / +3.46    │ +5.90 / +9.97    │ −3.36 / −3.68 │
│ 4to5+ │  29 │ 15 │ 51.7   │ +4.03 / +4.11    │ +6.33 / +8.66    │ −2.77 / −2.00 │
└───────┴─────┴────┴────────┴──────────────────┴──────────────────┴───────────────┘

条件：今日池的板数分布 N(stage)（由当日涨停池给出）

期望晋级家数   = Σ_stage  N(stage) × succ_rate(stage)
期望赚钱侧溢价 = Σ_stage  N(stage) × succ_rate(stage) × prem_avg(stage)  ÷ Σ 权重
期望亏钱侧开盘 = Σ_stage  N(stage) × (1−succ_rate(stage)) × fail_open_avg(stage) ÷ Σ 权重

档位映射：用 §3.1 同一套阈值（⛔ 不另立），把期望值折成 5 档
```

⚠️ **样本量纪律（照实写进页面）**：`3to4`(n=31) 与 `4to5+`(n=29) **贴近或低于 30 样本线**
⇒ 这两档的期望值**只呈现、不参与裁决**（沿用回测纪律 🔁-9）。
⚠️ 分布**右偏明显**（如 3to4 成功组 open 均值 +3.65 但中位 +3.46、close 均值 +5.90 中位 +9.97）
⇒ **默认展示中位数**，均值放 hover，⛔ 不用均值当门面（尾部极值会误导）。
⚠️ **必须同屏标注**样本量 `n` 与「**这是基于全历史阶段统计的条件期望，不是预测**」。
⚠️ 若今日池为空（盘前 / 数据缺）→ 整块显示空态，⛔ 不编造。


#### (b) T+2 ~ T+4 三情景推演

以 `turn_signal.dir` 为锚，给出**三个互斥情景**（纵向排列 · 用户偏好）：

| 情景 | 触发条件（机械可判） | 该情景下的效应档位 |
|---|---|---|
| **延续** | 晋级率 ≥ 前 3 日均值 ∧ 核按钮 ≤ 1 ∧ 炸板率 < 0.25 | 今日档位平移（不劣化） |
| **修复** | `turn_signal.dir='repair'` ∧ 核按钮连续 2 日下降 | 亏钱档位降 1~2 档 |
| **恶化** | 核按钮 ≥ 3 ∧ 炸板率 > 0.40 ∧ `zt_expand ≤ −0.30` | 亏钱档位升 1~2 档 |

- T+2 的中期溢价参考 = `promo` 的 `prem_close2` 经验分布（中位数优先，⛔ 不用均值——尾部极值会误导）。
- ⛔ **不给概率数字**（没有可靠校准）；给**触发条件**，让用户自己盯条件是否成立。
- ⚠️ 历史命中率**必须可回测**（`decision_audit` / `promo/backtest` 已有基础设施）→ 上线后按周回填，
  若命中率不显著则**如实展示并按 🔁-9 只呈现不裁决**。

## 6. 实时刷新的实现方式

**复用既有范式，⛔ 不另造机制**（`features/market/api/queries.ts` 已有实现）：

```ts
// src/features/market/api/queries.ts —— 既有（⛔ 不改，本页照用）
const pollMs = () => (inTrading() ? APP_CONFIG.pollIntradayMs : APP_CONFIG.pollOfflineMs)
//                                    ↑ 30_000                    ↑ 180_000
```

| 要点 | 做法 |
|---|---|
| 节拍 | `refetchInterval: pollMs`（传**函数**，每次调度重新求值 → 跨时段自动切节拍） |
| `staleTime` | 实时类 20s；日频类 300s |
| 后台标签页 | `refetchIntervalInBackground` 保持默认 `false`（不可见不轮询，省资源） |
| ⛔ **不假实时** | 「实时」= **基准日是今天 ∧ 正在交易时段**（两条都要）。往日 → 「最近交易日 · MM-DD」；今天非时段 → 「今日」。⛔ 都不带「盘中实时」 |
| 时段判定 | 一律走 `shared/lib/marketTime`（`inTrading` / `bjDateString`） |
| 钉死时钟 | 涉及「实时」的断言**必须在交易时段跑一遍**（`vi.useFakeTimers` + `vi.setSystemTime`，见 skill 记载） |

⚠️ **日频源（summary5d / promotion）当日 17:19 才更新** → 盘中它们天然是「昨日及更早」，
页面须**按数据自身的 `date` 字段标注**，⛔ 不要用「当前时间」暗示它是新的。

- 语义色：**赚钱/上行 = 红**，**亏钱/下行 = 绿**（A 股口径，⛔ 非美股）
