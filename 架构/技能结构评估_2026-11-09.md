# 技能结构评估 · 要不要把「龙头战法交易员 + 财神族」合并（2026-11-09）

> 对象：`~/.workbuddy/skills/` 下自建的 10 个技能（交易员 1 + 交易体系 1 + 财神族 7 + 狸猫终端 1）
> 方法：有效行重叠统计（≥40 字符的正文行，跨文件求交）+ 关键判据词频 + 体量估算
> 结论：**不合并成一个；但要把「判据副本」收口、把「方法论」降级。**

---

## 1. 体检数据（实测）

### 1.1 跨技能重复行：几乎为零

| 技能 | 有效行 | 出现在其他技能中的行 |
|---|---:|---:|
| 龙头战法交易员 | 500 | **0（0%）** |
| 财神-选股 | 532 | 3（1%） |
| 财神-盯盘 | 348 | 2（1%） |
| 财神-复盘 | 171 | 3（2%） |
| 财神-回测 / 中枢 / 客户推送 / 机构调研 / 交易体系 | 79–436 | **0** |

=> 这些技能**不是互相抄出来的**，是按系统边界切开的。合并不会去掉多少冗余，只会把 10 个入口压成 1 个巨无霸。

### 1.2 但同一套判据被反复复述（真正的副本在这里）

| 判据 | shared_rules.md | 交易员 | 财神-选股 | 财神-盯盘 |
|---|---:|---:|---:|---:|
| `5%` | 196 | **96** | 46 | 13 |
| `晋级率` | 79 | 51 | 21 | 8 |
| `09:25` | 91 | 26 | 37 | 9 |
| `断板` | 77 | 27 | 24 | 7 |

收益口径数字（策略 +61.05% / T+1 +25.22%）也在 `shared_rules` 与交易员 **各写了一份**。
这正是 `config/skill_contract.md` 自己定的铁律——「参数取源码或配置，不在技能复制第二套参数表」——目前**没有做到**。

### 1.3 体量：合并物理上就不可行

| 技能 | 字符 | 粗估 tokens |
|---|---:|---:|
| 财神-选股 | 85,345 | ≈ 53k |
| 财神-中枢 | 66,504 | ≈ 42k |
| 龙头战法交易员 | 49,375 | ≈ 31k |
| 龙头战法-交易体系 | 8,169 | ≈ 5k |
| 财神族合计 | ~455KB | **≈ 95k** |

合并后单次加载 ≈ 100k tokens —— 还没开始干活，上下文就没了。

### 1.4 触发歧义（比重复更该治）

- 「龙头战法交易员」与「龙头战法-交易体系」的 description **都以「龙头战法」开头**，用户一句「看下龙头」两者都会抢。
- 「交易员」的触发词含`竞价决策/今天买什么`，「财神-选股」的 description 也覆盖`09:25 竞价买入判定`。

## 2. 结论

| 判断 | 结论 |
|---|---|
| 10 个技能合并成 1 个 | ❌ 不可行：体量 ≈100k tokens，且会摧毁按需加载 |
| 财神族 7 个合并 | ❌ 不建议：跨域重复 <2%，它们本来就是「时段/系统边界」的切法 |
| 「交易体系」并入「交易员」 | ✅ 推荐：纯方法论 5k tokens，合并后消除触发歧义 |
| 判据上收 shared_rules，技能只留指针 | ✅ **最该做**：现在同一阈值有 3–4 份副本，改一处必漏 |
| 客户推送 / 机构调研 并入他件 | ⚠️ 不建议：它们是「发布」与「外部信源」两条独立职责，合并会模糊权限边界 |

**一句话**：技能数量不是问题，**判据副本**才是问题。合并解决不了副本，只有「单一源 + 指针」能解决。

## 3. 目标结构（保留分层，只收口）

| 层 | 现状 | 建议 |
|---|---|---|
| 宪法 | `shared_rules.md`（635KB） | 判据编号化（已有部分），成为**唯一**出现阈值的地方 |
| 总控 | 财神-中枢 | 不动（只索引不重复，定位正确） |
| 执行 | 选股 / 盯盘 / 复盘 / 回测 | 不动结构，正文改成「指针 + 本域差异」 |
| 发布 | 客户推送 / 机构调研 | 不动（权限边界清晰） |
| 岗位 | 龙头战法交易员 | 保留，吸收「交易体系」，判据改为引用 |
| 方法论 | 龙头战法-交易体系 | **降级为 reference 文档**，不再作为独立技能参与触发 |

## 4. 落地顺序（可逆、小步）

1. **降级**：把《龙头战法-交易体系》移到 `references/`（或改名 `龙头战法-交易体系-reference`），交易员 §0 加一段「体系见 references」。
   收益：少一次触发竞争，保留全部内容。
2. **收口**：交易员里 96 处 `5%`、51 处 `晋级率` 改为「见 shared_rules §x.y」；只在技能里保留**本域差异**（例如「深低开豁免」这种执行细则）。
3. **加锁**：新增一条契约检查（脚本/grep）——核心阈值在技能正文中出现次数 > N 即报警，防止副本重新长回来。
4. **触发词表**：在 `skill_contract.md` 补一张「谁在什么时段/什么问法下加载」，明确 交易员 vs 选股 vs 盯盘 的边界。

> ⚠️ 第 2 步是体力活，且会动到 31k tokens 的正文；建议先做 1、3、4（半小时级），确认无副作用再动 2。
