# 龙虎榜链路修复（2026-11-09）

> 目标：`/api/lhb/tencent` 与 `/api/card/lhb` 断更 41 天（最后一份 2026-09-29），恢复自动更新且**不再静默断更**。
> 结论：**两个独立故障叠加**；已修数据链路，并把它从"依赖单一 AI 任务"改成"常驻链路自愈"。

---

## 1. 现象

| 路由 | 最后一份 | 龄期 |
|---|---|---:|
| `/api/lhb/tencent`（`cache/lhb_YYYYMMDD.json`） | 2026-09-29 | 982h |
| `/api/card/lhb`（`cache/lhb_card_*.json`） | 2026-09-29 | 982h |
| `/api/lhb/hithink`（交叉校验源） | 11-05（且 11-03/04/06 缺） | 95h |

## 2. 双重根因（都已实测复现）

### 根因 A：任务被删，但没人发现

`~/.workbuddy/workbuddy.db` 实测：`【盘后】龙虎榜速览卡`（`automation-1145135d…`）
**于 2026-09-29 20:59 被软删除**，`config/tasks.yaml` 里对应条目标了 `retired: true`。
=> 每天 17:40/18:20 再没有任何东西去拉龙虎榜，而 `/api/lhb/tencent` 仍在路由里被终端消费。

### 根因 B：npx 全线 EPERM（即使任务还在也拉不到）

```
[lhb_fetch] npx 失败 rc=255: npm error code EPERM
npm error path /Users/zxl/.npm/_cacache/index-v5/...
```

`~/.npm/_cacache` 被 root 拥有（历史上跑过一次 `sudo npm`），此后**所有 `npx -y` 调用都失败**。
受影响的不止龙虎榜：`tx_query.py`（候选资金回填）、`intraday_pulse.py`（涨跌分布）同样静默失效。

### 为什么 41 天没人发现

`lhb_fetch.run()` 在抓不到数据时**仍然写一个空 JSON 并 exit 0** —— 文件在、时间新、内容空，
新鲜度面板与守护脚本都看不出异常。这是本次最该改的行为。

## 3. 修复（5 处）

| # | 改动 | 作用 |
|---|---|---|
| 1 | `common/npx_path.py` 新增 `npx_env()`：npm 缓存指向项目内 `.npm-cache`（可用 `LIMAO_NPM_CACHE` 覆盖） | 一次性修好**三处** npx 调用点，不碰用户目录、不需要 sudo |
| 2 | `scripts/lhb_fetch.py`：未披露/异常时**不落盘**，退出码 `2` | 空数据不再伪装成"已更新" |
| 3 | 新增 `scripts/lhb_ensure.py`：按 `common/trading_calendar` 取最近 N 个交易日，**幂等**补缺；写 `cache/lhb_status.json`；顺带补同花顺交叉源（best-effort，跳过当天防回落到昨日） | 缺口自动补齐，状态可读 |
| 4 | `scripts/pulse_fetcher.sh` 新增 `lhb_self_heal`：18:05 后每隔 10min 检查最近 3 个交易日，缺则补；失败 30min 内只告警一次 | **不再依赖 automation 是否被删**；删任务也不会再断 |
| 5 | `wealth_code/scripts/tx_query.py`、`scripts/intraday_pulse.py` 接入 `npx_env()` | 顺带修好两个"同因失效"的数据源 |

回滚：`LHB_SELF_HEAL=0`（或注释 `pulse_fetcher.sh` 里那一段）。
