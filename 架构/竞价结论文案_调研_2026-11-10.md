# 竞价结论文案 · 调研（2026-11-10）

> 范围：「高于预期 / 低于预期 / 没达到」这类**开票文案**从哪来、影响面多大、改的时候哪里会疼。
> 状态：**只调研，未改任何代码**（用户要求先看不动）。

## 1. 三层结构（改哪一层，成本差十倍）

```
① 判定层  ai_caliber.gap_zone(DEV)         → zone: above / ok / below
          expected_gap.py 逐票质量预期 E     DEV = 实际开幅 − E；DEV < −2.0 → below
② 状态层  signal_eval / auction_state      → signal_status: super / expected / weak / pending / reject / miss
③ 文案层  build_cards._STATUS_PLAIN        → 「超预期 / 符合预期 / 低于预期 / 待观察 / 没达标」
          _verdict_tag() / _v_tag_for()    → 上色 + 机械门禁下的摘除
```

- **改措辞** = 只动 ③ 的一张表；
- **改判定** = 动 ①（`EXPECTED_GAP_DEV_MIN = −2.0` 是唯一阈值），一处生效、全链路跟随——但它直接决定买不买，必须回放。

| `shared_rules` 文案铁律 | 多处 | 卡面用词的定义处 |

## 4. 三个隐蔽的耦合（改文案真正会踩的坑）

1. **颜色靠子串判**：`_verdict_tag()` 里 `if "低于预期" in verdict: color = neutral`
   —— 把文案改成「弱于预期」，颜色逻辑**静默失效**（变红，抢走买入票的视觉重点）。
2. **摘除逻辑也靠子串**：`_v_tag_for()` 的 `"符合预期" in v and "低于" not in v`
   —— 改「符合预期」会连带影响「机械没达标时摘掉✅」的行为。
3. **机械门禁是另一套词**：`机械达标 / 机械没达标` 与 `符合预期 / 没达标` 是**两条不同的判定**，
   卡面刻意不混（见 `shared_rules`「同屏不许自相矛盾」）。改文案时别把两套合并。

## 5. 结论

- **措辞可改，且很快**（半小时级）——但必须按「1 张表 + 3 处消费 + 30 条测试」清单走，漏一处就是静默错色或门禁拦截。
- **判定口径不建议顺手改**：`DEV < −2.0` 是当前唯一判据线，动它等于动买入规则，需要 34 日回放 + 样本外验证。
- 建议做法：先定「词表」（每个状态最终叫什么），我一次性改表 + 变色判断改成语义判断（不再用子串），再把测试字面量收进常量——**顺手把这三个坑填掉**。
