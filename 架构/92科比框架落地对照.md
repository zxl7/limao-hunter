> 2026-10-21 学习《92科比 · 短线情绪周期完整框架》后逐条对照。
> 前置：同日上午已落地「涨停强度 + 次日锚点链」（见 `涨停强度与次日接力链路.md`）。

## 一、最重要的一件事：`regime` 不是「周期位置」

学完这份框架，最该先纠正的认知偏差是这一条——系统原有 `regime` 与 92科比的四阶段**不是一回事**：

| | 系统 `regime` | 92科比四阶段 |
|---|---|---|
| 问的是什么 | **今天几度**（情绪绝对水平） | **这段行情走到哪了**（周期位置） |
| 取值 | ice / risk_off / neutral / risk_on | 低位震荡 / 主升 / 高位震荡 / 主跌 |
| 决定什么 | 当天能不能买、名额几个 | 这个阶段**该用什么手法、上多少仓位** |
| 数据 | 当日情绪分 + 核按钮 + 炸板率 | 晋级率/**溢价**的**变化方向** + 高度 + 广度 |

**为什么必须分开**：同一个「情绪 5 分」

- 出现在**低位震荡** → 试错良机（资金刚杀完高位，要找新方向）
- 出现在**高位震荡** → 随时转主跌（不赌穿越）

文档原话：「**周期位置不对，题材再好也是毒药**」。所以新模块 `core/cycle_phase.py` 只算周期位置，
⛔ 不改 `regime`、不改既有四档接力资格——两套并行，互不覆盖。

| 心法 | 落点 | 阈值 |
|---|---|---|
| **周期四阶段** | `cycle_phase.phase_of()` | 见下表 |

**四阶段判据**（每条都要「当日读数 + 方向」两条腿，单腿命中不下结论）：

| 阶段 | 判据（全部满足） | 仓位 |
|---|---|---|
| 主跌 | 溢价 ≤-1% **且** 上涨占比 <40% **且** 晋级率 <25% | 空仓 / 只做第二天尾盘 |
| 高位震荡 | 高度 ≥5 板 **且** 晋级率方向向下 **且** 炸板 ≥33% | 轻仓，不赌穿越 |
| 主升 | 晋级率 ≥30% **且** 溢价 >0 **且** 方向不向下 | 重仓 |
| 低位震荡 | 晋级率 <30% **且** 溢价没继续恶化 | 小仓位积极试 |

**中位区公式**（H = 市场最高板，⛔ H<5 不设中位区）：

```
低位 = 1~2 板（性价比区）      高位 = H-1 ~ H 板（地位确定性区）
中位 = 3 ~ H-2 板  → 排除
例：H=8 → 中位 3~6；H=5 → 中位只有 3 板；H=4 → 没有中位区（不裁决）
```

| 心法 | 为什么不做 |
|---|---|
| **题材预判（故事的传播力/想象空间）** | 这是**主观认知活**，无法量化为可复现规则。系统能做的是「等市场用价格确认」——即已落地的强度分与锚点判读。⛔ 不假装能预测题材级别。 |

## 三、值得专门记下来的三条「反直觉」认知

### 1. 竞价高开 ≠ 强势（这条和现有系统有冲突，必须分流）

文档 §6.2 原话：「**弱转强不要体现在竞价上**，最好是低开或平开后被资金买上去。竞价高开是做盘嫌疑。」

而系统今天上午刚把「强开 2%~5%」定为**唯一可执行窗口**。两者看似打架，其实**场景不同**：

| 场景 | 昨天状态 | 今天竞价该怎么读 |
|---|---|---|
| **弱转强**（文档讲的是这个） | 昨天炸板多 / 尾盘才封（封得弱） | 高开 = **做盘嫌疑**，要盘中验证 |
| **强者更强**（系统锚点链讲的是这个） | 昨天封得硬（早盘封、不炸板） | 强开 = 正常确认，可打 |

落地：`anchor_call.weak_to_strong()` 只在「昨天封得弱」时触发嫌疑判断；昨天封得硬的票不走这条。
⛔ 两套逻辑不许混用，否则会把「做盘高开」当成「强势确认」买进去。

### 2. 「越走越早」是龙头的**确认尺**，不是**否决闸**

文档：「涨停时间越走越早：三板的封板时间早于二板，四板早于三板。」

系统落地为 `fbt_acceleration()`，但**只用来判断「能不能叫龙头」**，不用来否决买入。
理由：时间没加速的票仍可能是好的接力对象（比如刚启动的首板），只是不配「龙头」这个称呼。
把加分尺做成否决闸，会把大量正常机会砍掉。

### 3. 「没有爆量检验的不能确认为龙头」

这条很容易被忽略但很有用：连板过程中没出现过**放量分歧**（≥1.5 倍）的票，
说明它没被市场真正检验过——**这只是「没分歧的连续上涨」，不是「被检验过的龙头」**。

落地：`volume_check()` 返回 `passed=None/False/True`，只影响「龙头」身份的认定与叙事措辞，
⛔ 不直接拦买入。

## 四、当前生效的完整判断顺序（9:25 裁决链）

```
⓪ 环境防守腿（regime + 今晨读数）        → 名额压到 1 只 / 0 只
① 无竞价数据                             → 观察
② 超 5% 硬线                             → 放弃
③ 盘后预案＝回避                          → 放弃
④ 低于预期                               → 放弃
⑤ 没红开                                 → 观察
⑥ 红开但没量（诱多）                      → 观察
⑥b ⚓ 锚点闸（昨天大将军今天破预期/低开）   → 该线今天不碰
⑥c 🎯 中位股闸（既不是最高板也不是低位）    → 不占名额     ← 本轮新增
⑦ 🐣 跟风闸（同线核心已断板且高出 ≥2 板）   → 观察
⑧ 🧊 方向资金失血                         → 观察
⑨ 🧭 位置闸（高位 + 断板≥3日重启）         → 观察
⑨b 🐉 老龙复燃闸                          → 观察
⑩ 🛡️ 派发特征（换手大+封单薄+封得晚）       → 观察
⑪ 🚧 后排接力闸（有前排却买小弟）           → 观察
⑫ 候选买入 → 按地位 → 身位 → 预案 → 板数 排名额
```

**周期位置（`cycle_phase`）不在这个链条里**——它是**上游**：决定「今天该用哪套手法」，
以文字建议形式进卡面，⛔ 不参与逐票裁决。这是刻意的：周期判断的置信度天然低于硬数据，
让它直接决定买不买，风险大于收益。

## 五之二、P1 落地详情（2026-10-21）

**做了什么**：把 `cycle_phase.phase_of()` 的结论送进三张卡的卡面。

| 卡 | 位置 | 行数 | 理由 |
|---|---|---|---|
| 📊 盘后候选 eod | 📡 大盘环境之后、「数据源」之前 | 3 行（位置 + 方向证据 + 该这么打） | 盘后时间充裕，方向证据要留 |
| ⚡ 竞价验证 verify | 净值回撤线之后、「🤖 今日买入」之前 | 2 行（位置 + 该这么打） | 早上时间紧，位置 + 打法够决策 |
| 📊 盘前预测 panqian | 模块① 盘前定调之后 | 2 行（同上） | 不占模块编号（模块①~⑦ 结构是铁律） |

**渲染样例**（今日真实数据）：

```
🌊 行情位置：低位震荡（试错期）
　　前几天溢价最低到 -2.13%，现在翻正 → 正在从亏钱里修复 ——
　　高位杀出来的钱在找新方向，低位新题材最容易起来
　　🎯 这一段该这么打：找下一个龙头种子（新方向首板 / 1进2），别追高位残局 · 小仓位但积极试
```

**三条设计约束**（都是实测踩出来的）：

1. **卡面用 `shift`（只讲方向），不用 `why`（含当期读数）**
   第一版直接把 `why` 上卡，结果「晋级率只有 28%」与 📡 大盘环境块的「晋级率 30.4%」重复
   —— 违反「同一件事实全卡只说一次」。故 `phase_of()` 返回两个字段：
   `why`（完整判据·含读数·供日志复盘）与 `shift`（只讲从哪来、往哪去·卡面用）。

2. **基准日标注只在跨日时出现**
   周期是**收盘后**才成立的判断。verify 卡在次日 09:26 读到的仍是昨日矩阵 →
   必须标「（10-20 收盘盘面）」，否则会被读成今天的位置。

3. **诚实降级：位置不明 / 判断异常 → 整块不渲染**
   ⛔ 不占位、不硬凑一句「位置不明」。周期判断炸了也返回空 list，不许影响整张卡。

**决策留痕**：`pool_call.meta.cycle_phase` 记录当时的阶段/仓位档/手法，
供复盘回答「当时是什么位置、所以这么判」。⛔ **只记录、不参与裁决**。

**测试**：`tests/test_cycle_phase_card.py`（10 例）锁住上面三条约束 +
「内部标记不上卡面」+「PHASE_PLAY 源头文案不含 ⛔」。

**踩坑记录**（值得记住）：
中位股闸的市场高度最初做了「磁盘兜底读 `zt_history`」，导致 `test_defense_gate` 5 例
读到真实生产文件而红。修复＝**去掉磁盘兜底**，改为「显式参数 → `environment.max_boards`
→ `zt_rows` 现算 → 都没有就不裁决」，与既有 `line_cores`/`sector_flow` 的「显式传参即隔离」
约定一致。同类注意：给 `build_*_card` 加会读盘的新块时，务必同步在测试的 `_quiet()` 里隔离。

## 五之三、P2 落地详情：龙头身份与确认尺打通（2026-10-21）

### 问题：关于「谁是龙头」有三套东西，从来没串起来

| 来源 | 判什么 | 输出 |
|---|---|---|
| `expectation_ai.dragon_three_diagnosis` | 带领性 / 突破性 / 唯一性 | 真龙头 / 准龙头 / 跟风 |
| `leader_cycle.annotate` | 五维证据（竞争/跟随/分歧/启动/催化）+ 连续性 | 龙头 / 准龙头 / 跟风 + confirmed/pending |
| `anchor_call.fbt_acceleration` / `volume_check` | 92科比两把尺 | accelerating / passed |

结果：卡面上一只票算不算龙头，取决于哪套先跑；两把尺算出来**却没人用**。

### 解法：`core/dragon_confirm.py` 合成一个认定

```
confirm(row, series) → {level, label, checks[5], narrative, acceleration, volume}
```

五档认定：

| 等级 | 条件 | 标签 |
|---|---|---|
| `confirmed` | 五维 confirmed **且** 两把尺都过 | 🐉 龙头（红） |
| `confirmed_thin` | 五维 confirmed **但**尺没全过 | 龙头·未验证（橙） |
| `partial` | 五维没 confirmed **但**两把尺都过 | 准龙头（形态像）|
| `pending` | 五维没 confirmed、尺也没全过 | 准龙头 |
| `not_dragon` | 数据不足或明确不是 | 跟风（不标） |

### ⛔ 最重要的边界：两把尺是「叙述层」，不是「资格层」

用户 2026-09-24 已拍板「地位优先 + 五维确认」是龙头资格的**唯一判据**。所以：

- 五维 confirmed 但尺没过 → **保持龙头身份，不降级**，只标注「容易被一波流带走」
- 五维没 confirmed 但尺都过 → **仍不升龙头**，只标注「形态像，还差证据」

两把尺只改变**措辞**，绝不改变 `identity_role` 字段。这把「不推翻已拍板的规则」
和「让新证据真正发挥信息价值」两件事同时做到了。

### 一个实测发现：叙述必须带区分度

第一版三只票的 `narrative` 一模一样（都只说「五项证据没凑齐」），两把尺的信息全丢了。
真实数据一跑就露馅：

| 票 | 时间加速 | 爆量检验 | 改后叙述 |
|---|---|---|---|
| 吉大正元 | ✅ 越走越早 | ❌ 爆量 6.5 倍后还在放量 | 「形态上**涨停时间越走越早**」 |
| 大业股份 | ❌ 时间波动大 | ✅ 3.1 倍后缩量 | 「形态上**做过爆量检验**」 |

同样的「准龙头」结论，但两只票的**短板完全不同**——这才是读者要的信息。

### 序列取数：必须判「相邻交易日」，不能只看「那天在不在池里」

`series_of()` 首版只检查「该日在 `rows` 里有没有这只票」，`zt_history` **整天缺文件**时
会直接跳过、把两段行情连成一波（会让两把尺全失真）。修复＝注入 `_default_adjacent()`，
走 `common.trading_calendar` 判断两日之间有没有夹着交易日，有就断。

⛔ 不用 `weekday()`：会把「工作日休市」（中秋/国庆调休）错当交易日，隔着假期的两次涨停
会被误连（与 `leader_cycle._adjacent` 2026-10-09 修的同一个坑）。

### 卡面落点

个股标题行插一个极短标签（只给前两档，准龙头/跟风不标）：

```
📊 吉大正元(003029) 4板 符合预期 +1.20% [龙头] ✅符合预期
```

⛔ 不标准龙头与跟风：每只票都挂身份＝等于没身份。

### 「只差催化」替代路径（2026-10-21 用户拍板 A·已默认开启）

**问题**：`catalyst == "sustained_verified"` 要求 `kind∈(政策/订单/产业事件/技术)` 且
`verified=true`，而 `cache/newsflash_history/daily_*.json` **全部 `kind=None`/`verified=None`**
→ catalyst 维永远 unknown → `confirmed` 实际不可达 → 龙头标签是死代码。

**用户决策**（14:59 选 A）：开启替代路径，同时把「补新闻源 kind/verified」排进计划（治本）。

**判据设计（⛔ 修正过一次，必须记住）**：

替代路径的条件 = `leader_cycle.annotate` 原文 confirmed 的五条，**只把催化那一条**
从 `sustained_verified` 换成 `unknown`：

```
carry > 0 ∧ continuous ≥ 3 ∧ sector_follow == sustained
∧ divergence == recovery_with_carry ∧ launch ∈ (new_direction_candidate, existing_direction)
∧ catalyst == unknown            ← 唯一改动
```

⚠️ **首版我额外加了「competition ∈ (market_only, theme_winner)」和「两把尺全过」，
实测永远 0 只命中**：

| 我多加的条件 | 为什么是错的 |
|---|---|
| competition | **原文 confirmed 根本不含这一维**（那是外层 `if confirmed and (competitive or ...)` 的另一条）。实测 competition 全是 `not_in_cohort`/`promoted`，加了就是死代码 |
| 两把尺全过 | 两把尺是**叙述层**，不进资格层。加进去等于自己推翻自己的分层设计 |

**实测结果**（10-20 真实候选 11 只）：

| 票 | 五维 | 两把尺 | 认定 |
|---|---|---|---|

**同步升级 `leader_role`（只升不降）**：

## 五之四、P3 落地详情：阶段连续天数（2026-10-21）

92科比：「主跌第二天尾盘试、第三天必出」——这条规则的前提是「第几天」可得。

- 状态文件 `cache/cycle_phase_state.json`：`{phase, date, streak, since, updated}`
- `cycle_phase.track_state()`：比对旧状态，同日幂等、跨日递增、阶段变更重置
- `streak_note()`：只对**主跌/主升**给天数

| 阶段 | 提示 |
|---|---|
| 主跌第 1 天 | 别急着抄 |
| 主跌第 2 天 | 只允许尾盘拿一点点试，明天必须走 |
| 主跌第 ≥3 天 | 早过了试探窗口，等新周期起来再说 |
| 主升第 N 天 | 刚起可以上 / 位置已经不低 |

⛔ **低位震荡 / 高位震荡不给天数**：那两个阶段没有「第几天该做什么」的节奏，
硬给一个数字只会让人以为有个不存在的节奏。

**幂等铁律**：同一基准日多次渲染只算一天（卡面渲两次、盘中反复重算都吃这条）。
`_cycle_phase_block(persist=False)` 供离线重渲/测试使用，零副作用。

### 顺带修掉一个「首次运行必然失效」的坑

`phase_of()` 判主升时要求方向 `in ("up","flat")`，而方向靠 `trend.history` 至少 2 期才能算。
结果：**系统首次运行（history 还没攒起来）永远判不出主升**，明明在涨的行情会被打成位置不明。

修复：改为「方向 **不是** down」——缺方向 ≠ 有坏方向。这条是测试写的时候撞出来的，
不是设计时想到的。

## 六、一句话备忘

**先认位置，再认强弱，最后才认票。**
位置（四阶段）决定手法与仓位；强弱（涨停时间/爆量/加速）决定谁是龙头；
锚点（次日竞价）决定今天动不动手；身位（前排/中位/后排）决定具体买哪只。

⛔ 顺序颠倒就会变成：先看上某只票 → 再给它找理由 → 最后才想起来看大盘。
